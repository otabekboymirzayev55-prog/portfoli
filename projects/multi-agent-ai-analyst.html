Multi-Agent AI Analyst

A LangGraph workflow that answers business questions using document retrieval, read-only SQL and bounded arithmetic.

Python / LangGraph / FastAPI / React

Source code ↗Public interface (AI setup pending) ↗

Gemini verified locally · public AI setup pending

The problem

Business questions need different evidence. A database can count cancellations, while document notes explain why a customer left. Routing every churn question to SQL loses that distinction.

How it works

A supervisor selects specialist agents, gathers evidence, generates an answer and sends it through a critic. FastAPI exposes the workflow to a React interface. Model and embedding calls use the official Gemini API.

Question → supervisor → retrieval / SQL / arithmetic → evidence → answer → critic

Engineering decisions

  1. Route by the evidence a question requires

    Explicit document requests and cancellation reasons go to retrieval. Mixed questions can collect both document and SQL evidence.

  2. Bound the tools

    SQL uses a read-only connection. Calculation uses restricted arithmetic rather than arbitrary Python execution. Sessions are isolated and history is bounded.

  3. Treat verification as a gate

    A draft rejected after the revision limit is replaced with a clear uncertainty response. A new Gemini index is kept separate from the former embedding space.

What was checked

19 automated checks passed. In local API and browser tests, the system retrieved the documented reasons for Blue Harbor and Crestline leaving. A separate SQL question returned total sample revenue of $5,390; arithmetic returned 5 for (12 + 8) / 4.

Verification recorded October 30, 2026. Automated checks and live service checks cover different things.

Current limits

These are sample-data checks, not a general reasoning benchmark. The public interface exists, but its Render API still needs the Gemini secret and a hosted document index. Local success does not establish public service availability.

Next step

Configure the hosting secret and persistent index, then repeat the document and database checks against the public API.
