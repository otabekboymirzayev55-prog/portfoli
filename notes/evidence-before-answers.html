Choose the evidence before choosing the answer

An implementation note from the portfolio projects.

The failure

In the Multi-Agent Analyst, a real test asked why two customers had left. The workflow selected SQL and returned an incomplete explanation. The database could support quantitative analysis, but the cancellation reasons lived in document notes. The available tool was not the right evidence source.

Separate quantities from explanations

“How many customers left?” and “Why did they leave?” share vocabulary but require different evidence. Quantitative questions can use a read-only database query. Explicit document requests and cancellation reasons should trigger retrieval. A question asking both needs both sources before generation.

Make important routing requirements explicit

The router now recognizes explicit source requirements before the general model routing step. It tracks whether the required source has already supplied evidence. This avoids treating the first successful tool response as enough for every part of a question. The rules are deliberately narrow; more ambiguous wording still needs evaluation.

Check the whole path

A routing unit test catches the regression, but the useful check follows the path through retrieval, generation and verification. In the local test, the answer correctly identified price sensitivity for Blue Harbor and a missing inventory integration for Crestline. Those facts came from the sample documents.

Do not mistake a critic for a guarantee

A model critic can approve an incomplete answer. Evidence selection and clear source requirements are important before that step. If a draft is still rejected after the revision limit, the application returns uncertainty rather than the rejected draft. These checks are safeguards, not a proof of factual correctness.
